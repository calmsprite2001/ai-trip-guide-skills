# 打卡点与机位 · 每城一册

> 机位不是"这个地方很美"，而是**"站在哪、几点站、怎么拍、怎么过去"**。
> 四个都给全了才算合格；只写"很美"等于没写。

---

## 一、机位分几类（按类型去找，别瞎搜）

| 类型 | 典型点位 | 搜索词模板 |
|---|---|---|
| **城市天际线 / 全景** | 观景台、山顶、跨江大桥 | `XX 最佳观景点` `XX 俯瞰` |
| **古建 / 人文地标** | 寺庙、城墙、老街区、石窟 | `XX 机位` `XX 拍照` |
| **自然景观** | 丹霞、湖泊、沙丘、雪山 | `XX 日落机位` `XX 日出` |
| **夜景 / 灯光** | 桥、塔、夜市、江景 | `XX 夜景机位` `XX 亮灯时间` |
| **街拍 / 生活感** | 老巷、市场、车站、早市 | `XX 扫街` `XX 人文` |
| **小众 / 网红点** | 咖啡馆、书店、天台、楼梯 | `XX 小众机位` `XX 隐藏机位` |

**每城覆盖 2–3 类**，不要全是网红点 —— 全景 + 地标 + 一个当地生活感，是最稳的组合。

---

## 二、每个机位必须给六要素

| 要素 | 落在哪个字段 | 说明 |
|---|---|---|
| **机位名** | `s` | 能在地图上搜到的名字 |
| **怎么拍** | `t` | 构图 / 焦段 / 前景 / 光线方向 |
| **几点拍** | `at` | 具体时点（`日落前 40 分`）或时段（`19:00 前后`） |
| **导航关键词** | `nav` | 默认同 `s`；机位名和景点不同名时必填 |
| **怎么去** | 写进 `t` | 交通 / 步行 / 坐电梯 / 是否要门票 |
| **人流情况** | 写进 `t` | 几点后旅游团上来、要不要提前占位 |

⚠️ **只有"XX 很美"这种描述，不算机位。** 六个至少要齐前五个。

---

## 三、怎么找（来源与手法）

**来源：小红书高赞攻略**（指定）+ 高德地图定位 + 日落时间表

1. **搜索**：`城市/景点名 + 小红书 + 机位 / 攻略 / 打卡`
2. **取高赞**：**收藏数优先**（比点赞更能说明实用）；**3 条以上不同作者**提到才算共识
3. **定位**：拿机位名去高德搜 —— **能搜到才写 `nav`，搜不到就留空**（否则导航到沟里）
4. **算光**：日出日落时间用「XX 城市 日落时间 X 月」查 —— 这是硬数据，要准
5. **剔软广**：带商家名 / 价格引导 / 联系方式的，剔除

⚠️ 小红书是 UGC，**页面标注写「据小红书高赞攻略整理」，不标「已核验」**（见 `sources.md`）。

## 四、避坑清单

| 坑 | 说明 | 对策 |
|---|---|---|
| **网红机位已失效** | 点位被拆 / 被封 / 围挡 | 优先用**发布时间近**的帖，超 1 年打折 |
| **季节差异大** | 树叶、水位、花海、雪线随季节变 | 按出行月份搜，别参考错季 |
| **机位名搜不到** | 是"野点"，没有正式 POI | **不写 `nav`**，改写成"从 X 往 Y 走" |
| **安全** | 马路中间、铁轨上、危楼顶 | **一律不推荐** —— 出事是大事 |
| **要门票** | 有些机位在景区内 | 必须写清"需门票" |
| **人流峰值** | 热门机位排队 | 写清"几点前到" |
| **无人机** | 多数景区禁飞 | 别主动推荐，除非确认可飞 |

## 五、数量与排序

- **每城 5–8 个**，覆盖 2–3 类（见上）
- **按行程顺序排，不按类型排** —— 用户是一天一天走的，不是按主题走的
- 标注**顺路的**（就在当天某个景点旁边），这类性价比最高

## 六、落到数据

```js
shots:[
  { s:'鸣沙山沙脊日落', nav:'鸣沙山月牙泉', at:'日落前 40 分',
    t:'19:20 日落。提前 40 分钟爬上沙脊占位，长焦压缩沙脊线条。在景区内，需门票。' },
  { s:'莫高窟九层楼', nav:'莫高窟', at:'上午顺光',
    t:'标志性机位，上午正面顺光。窟内严禁拍照。' }
]
```

- `at` 会渲染成蓝色小标签（最佳时段）
- 每条自动生成「导航去这里」按钮（高德 URI，点一下直接跳）
- **`nav` 尽量填**，哪怕和 `s` 一样也写一遍，方便以后改

字段定义与渲染约定 → `data-schema.md` 第 3.5 节
