# AI 旅行攻略 Skill 套件

> 一句话把旅行需求丢给 AI，自动产出一份**手机端可打开、数据可溯源**的完整攻略页，再一键做成小红书图文卡片。

这套东西由两个 Skill 组成，可以单独用，也可以串起来跑：

| Skill | 干什么 | 产出 |
|---|---|---|
| **`trip-guide-builder`** | 从"成都去山西，11/1-11/5"这种一句话需求出发，自动追问 → 设计行程 → 核实票务 → 配图 → 生成 HTML 攻略 → 发布上线 | 手机端攻略页（在线链接 + 离线单文件） |
| **`social-card-render`** | 把攻略页截图和素材，排成社交平台图文卡片 | 小红书 / 朋友圈 1080×1440 图片 |

---

## 它到底能做什么

不是"生成一段行程建议"，而是**产出一个能直接拎着出门的东西**。

真实产出示例（山西 5 天 4 晚，大同 → 太原 → 平遥）：

- **行程按地理顺路排**——识别出大同在北、太原居中、平遥在南，安排一路南下不走回头路
- **票务逐条落到官方来源**——悬空寺登临票每日限量多少张、几点放票、哪个小程序买；云冈石窟要提前几天预约
- **避坑检测**——自动发现"山西博物院周一闭馆"而把参观日排到周三；发现"11/1 起民航转冬春航季，大同机场时刻表会重排"并在页面标注
- **抢票倒计时**——哪个票最难抢、什么时候开抢，做成一页倒计时，手机打开实时刷新
- **每城一张原创水彩长卷封面**——风格统一，用母版图做图生图保证一致性
- **离线兜底**——图片全部内联的单文件 HTML，山里没信号也能翻

> 🔍 **数据诚实是设计核心**：这套 Skill 不内置任何景点库、票价库、店铺库。
> 每一个地址、电话、票价、预约规则，都是**跑这一次现查的**，并在页面底部逐条标注来源与核验日期。
> 查不到的（比如某家餐厅的电话）宁可不放，也不编。

## 快速开始

### 前置条件

**必须有的：**

| 依赖 | 最低版本 | 用途 |
|---|---|---|
| **WorkBuddy 或 Codex** | — | 本套件是 Skill，需要一个支持 `SKILL.md` 规范的宿主客户端来加载。WorkBuddy 原生支持；Codex 同样可加载技能目录 |
| 联网搜索能力 | — | **硬依赖**。所有票务、时刻、预约规则都是现查的，没有搜索能力这套东西就是个空壳 |
| Python | 3.11+ | 跑 `scripts/` 下的脚本 |
| Node.js | **22+** | CDP 截图用，依赖原生 `WebSocket`（22 以前没有） |
| Chromium 系浏览器 | — | Edge / Chrome / Chromium 任选，无头模式截图用 |

**可选（缺了有降级路径，不影响主流程）：**

| 依赖 | 缺了会怎样 |
|---|---|
| 图片生成能力 | 降级为「用户自备照片」或「CSS 纯色封面」 |
| 网站发布能力 | 降级为「直接把 HTML 文件发给用户」，离线版照样能用 |

**明确不需要：** 任何金融/行情类数据连接器。旅游数据不在里面。

### 安装

**一键装（推荐）：**

```bash
git clone https://github.com/<your-name>/ai-trip-guide-skills.git
cd ai-trip-guide-skills
python install.py            # 自动探测 skills 目录 + 拷贝 + 环境自检
```

`install.py` 会自己找 WorkBuddy / Codex 的 skills 目录。想指定位置加 `--target`，
只想看看会发生什么加 `--dry-run`（不写盘）。详细说明见 [INSTALL.md](INSTALL.md)。

**手动装：**

```bash
# 1. 克隆仓库
git clone https://github.com/<your-name>/ai-trip-guide-skills.git

# 2. 把两个 skill 目录拷进客户端的 skills 目录
#    Windows:
xcopy /E /I ai-trip-guide-skills\trip-guide-builder  "%USERPROFILE%\.workbuddy\skills\trip-guide-builder"
xcopy /E /I ai-trip-guide-skills\social-card-render "%USERPROFILE%\.workbuddy\skills\social-card-render"

#    macOS / Linux:
cp -r ai-trip-guide-skills/trip-guide-builder ~/.workbuddy/skills/
cp -r ai-trip-guide-skills/social-card-render ~/.workbuddy/skills/

# 3. 重启客户端（或新开会话），让它扫描到新 skill
```

> 注意：拷的是**整个文件夹**，不要拆散。`SKILL.md` 是入口，`references/` `scripts/` `assets/` 必须跟它同级。
> 已存在的 skill 会被 `install.py` 自动备份成 `<名字>.bak-<时间戳>`，不会直接覆盖。

### 环境自检

装完先跑一次自检，确认浏览器、Node、Python 都探测到了：

```bash
python ~/.workbuddy/skills/trip-guide-builder/scripts/_env.py
```

正常输出类似：

```
浏览器 : C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe
node   : C:\Program Files\nodejs\node.exe
python : C:\Python311\python.exe
输出根 : D:\旅行攻略
```

任何一项显示 `!! 未找到`，用环境变量覆盖：

```bash
export BROWSER_PATH="/path/to/msedge"       # 指定浏览器
export NODE_PATH_BIN="/path/to/node"        # 指定 node
export TRIP_GUIDE_OUT="/path/to/output"     # 指定攻略输出根目录
```

## 怎么用

装好之后，直接跟 AI 说人话就行。

### 用 trip-guide-builder

```
帮我做旅行攻略
```

它会主动问你（这三个是入口问题，不用你一次性想清楚）：

1. **想去哪几个城市？从哪出发？** —— 没想好它会给你四种组合类型挑（环线 / 双城 / 单城深度 / 放射）
2. **城市之间想坐什么？** —— ✈️ 飞机 / 🚄 火车 / 🚌 大巴 / 🚗 包车，或者让它按距离帮你定
3. **这趟更看重什么？** —— 古建历史 / 美食 / 拍照打卡 / 购物手信（可多选）

之后它会分批问齐人数、票务状态、节奏偏好、住宿档位，然后开始干活。

产出的文件在 `TRIP_GUIDE_OUT/<YYYYMMDD>_<主题>/`：

```
20260913_山西古建5日/
├── 山西古建5日·旅行攻略.html          # 主攻略，8 个 Tab
├── 山西古建5日·旅行攻略_离线版.html    # 图片全内联，单文件
├── img/final/                          # 配图（总览 + 每城一张）
├── publish/                            # 发布目录（有 index.html 双入口）
└── 交付说明.md
```

### 用 social-card-render

```
把这个攻略做成小红书图文
```

卡片用 HTML 排版（保真度远超 PIL 手排），再用无头浏览器按元素截图：

```bash
python scripts/render.py \
  --root "D:/your-project" \
  --html "cards.html" \
  --out "D:/your-project/final"
```

每张卡片是一个 `<section class="card" id="cN">`，画布 1080×1440（小红书 3:4）。

## 设计原则

这套 Skill 有两条不肯妥协的规矩，也是它跟"让 AI 随便写段行程"的区别所在：

### 1. 数据必须可溯源

来源分五层，每条可核验数据都要能落到某一层并在页面上标明：

| 层 | 来源 | 标法 |
|---|---|---|
| S1 | 用户提供 | `用户提供` |
| S2 | 官方一手源（12306 / 景区公众号 / 高德 / 气象台） | `已核验 · 日期` |
| S3 | 联网搜索 | `已核验` 或 `据公开信息` |
| S4 | 客户端能力（配图、发布） | — |
| S5 | 模型先验 | 仅限通用常识 |

**三层红线：**

1. 电话号码、门牌地址、票价、预约规则、起售时刻 —— 必须走 S1/S2/S3，**查不到就留白标注，绝不编造**
2. 用户给的旧行程书**默认全部过期**，当线索不当事实
3. 核验日期必须写进页面 —— 没有日期的核验等于没核验

> 一份"框架完整 + 数据诚实"的攻略，远好过"内容丰满 + 数据可疑"的攻略。

### 2. UGC 与官方源严格分开

小红书高赞攻略**只用**于：景点玩法、拍照机位、排队实况、避坑经验。
票价、预约规则、开放时间、地址电话一律走官方源，页面标注写「据小红书高赞攻略整理」，**不标「已核验」**。

## 已知限制

说清楚哪些做不到，省得踩坑：

| 限制 | 说明 |
|---|---|
| **没有内置数据库** | 不存任何景点/票价/店铺数据，每次都是现查。断网 = 不可用 |
| **依赖宿主客户端** | 它是 Skill 不是独立程序，需要 WorkBuddy 或 Codex 这类支持 `SKILL.md` 规范的客户端加载 |
| **港澳台需补模块** | 主流程可用，但需额外补出入境证件与当地交通模块；出境不在范围内 |
| **票务有时效性** | 票价和预约规则会变，攻略产出后出行前**务必按官方最新公告再核一遍** |
| **Windows 路径问题** | 部分 Windows 环境下 Bash 工具 PATH 会间歇为空，脚本调用建议用 Python `subprocess` 传中文路径 |
| **图片生成有成本** | 用 AI 生成配图会消耗额度（每张约 5–10 点），开工前会先告知总量；没有额度可走降级路径 |

## 常见问题

**Q：能不能不联网用？**
不能。这套东西的核心价值就在于"现查最新数据"，离线就是个空壳。产出的**攻略页**可以离线看（有专门的离线版），但**生成过程**必须联网。

**Q：必须要 WorkBuddy 吗？**
可以用 WorkBuddy，也可以用 Codex —— 两者都能加载 `SKILL.md` 规范的技能目录。
个别能力（比如"发布成在线链接"）依赖宿主客户端提供，Codex 下如果没有对应能力，
会自动走降级路径：直接把 HTML 文件交付给你，离线单文件版照样能用。

**Q：装完怎么确认能用？**
先跑 `python scripts/_env.py` 自检，确认浏览器、Node、Python 都探测到了。
然后在会话里说「帮我做旅行攻略」，能正常进入追问流程就说明加载成功。

**Q：为什么票务信息要标核验日期？**
因为**它们会变**。景区会调价、会改预约规则、会换闭馆日。标了日期，用户才知道这条信息是什么时候的，值不值得信。

**Q：可以用在境外目的地吗？**
框架能用，但 `references/regions.md` 的适配是围绕国内写的（12306、高德、景区公众号这套体系）。境外要自己补交通与票务模块。

**Q：生成一份攻略要多久？**
取决于目的地的复杂度和核实工作量。核实的环节最耗时（每个票价、时刻、预约规则都要逐条查官方源）。
